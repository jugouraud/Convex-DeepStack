## A11Y

- **FE.A11Y1 M** Define the project's applicable accessibility standard and test scope. Unless a higher or different binding requirement applies, use WCAG 2.2 Level AA as the default product target; do not claim conformance from automated tests alone.
- **FE.A11Y2 M** Ensure meaningful functionality works via keyboard without traps; use native controls or established widget keyboard patterns, including Escape/arrow/Enter/Space behavior where applicable.
- **FE.A11Y3 M** Keep focus visible and predictable. On dialogs, route transitions, overlays, disclosures and validation, move or restore focus intentionally where interaction warrants.
- **FE.A11Y4 M** Provide correct accessible names, roles, values, states, descriptions and relationships; prefer native semantics and use ARIA only to supplement what HTML cannot express.
- **FE.A11Y5 M** Preserve sufficient color contrast and non-color cues for meaning; include focused, disabled, hover, pressed, selected and error states when relevant.
- **FE.A11Y6 M** Support text resizing, zoom and reflow; do not block pinch zoom or require horizontal scrolling for ordinary content where the applicable accessibility standard forbids it.
- **FE.A11Y7 M** Keep reading/DOM/focus order meaningful; do not create duplicated announcements or offscreen interactive controls through hidden responsive variants.
- **FE.A11Y8 M** Give forms programmatic labels, instructions, error association and accessible validation feedback; never rely only on placeholders or color.
- **FE.A11Y9 M** Provide necessary nontext alternatives and captions/transcripts when applicable; decorative media must not add distracting or misleading accessible output.
- **FE.A11Y10 M** Respect reduced-motion and flashing restrictions, avoid auto-moving focus without user intent, and give controls for moving/auto-updating content where required.
- **FE.A11Y11 M** Test changed critical widgets with keyboard and, when risk warrants, representative screen-reader/browser combinations; automated axe-like scans cover only part of accessibility.
- **FE.A11Y12 S** Prefer simple DOM composition and native dialog/disclosure/form behavior before custom ARIA widget infrastructure; use the WAI-ARIA Authoring Practices Guide for complex patterns.
- **FE.A11Y13 M** Use live regions/status messages sparingly and correctly: announce meaningful async status without repeatedly interrupting users or duplicating focus announcements.
- **FE.A11Y14 M** Ensure pointer/touch target usability, avoid gestures as the only mechanism, and provide alternatives to dragging where the applicable standard requires them.
