## UX

- **FE.UX1 M** Make the primary task recognizable and achievable; each actionable control needs an understandable purpose, affordance and outcome.
- **FE.UX2 M** Provide timely feedback for consequential actions and asynchronous states: pending, success, failure, empty result, partial result and recovery where relevant.
- **FE.UX3 S** Prefer familiar platform conventions, predictable navigation and progressive disclosure to excessive user memory demands or custom interaction novelty.
- **FE.UX4 M** Prevent avoidable destructive mistakes through context, confirmation or undo proportional to risk; make irreversible operations and their consequences clear.
- **FE.UX5 M** Preserve user-entered work through recoverable failures when feasible; avoid losing form state on transient network problems, rerenders or redirects.
- **FE.UX6 S** Write concise, specific and actionable UI copy; identify what went wrong and how to recover without exposing internal errors or blaming users.
- **FE.UX7 S** Define all meaningful states before implementing polish: first load, slow network, no data, validation error, permission denial, partial failure and long/translated content.
- **FE.UX8 M** Avoid deceptive interfaces, hidden costs, disguised advertising, misleading consent, unauthorized autoplay and interactions that obscure user choices.
- **FE.UX9 S** Test actual task flow rather than isolated visual components alone; consider latency, keyboard-only operation, small screens and users unfamiliar with domain vocabulary.
- **FE.UX10 S** Prefer functional information hierarchy, clarity, spacing and legibility over decorative animation, visual density or trend-driven layouts.
