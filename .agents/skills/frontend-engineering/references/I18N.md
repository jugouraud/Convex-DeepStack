## I18N

- **FE.I18N1 M** Identify supported locales, scripts, writing directions and formatting needs before implementing internationalized routes/components; do not hardcode English assumptions into reusable logic.
- **FE.I18N2 M** Externalize user-facing text that must be translated, including validation errors, accessibility names, dates and empty states; avoid concatenating translated fragments with incompatible grammar.
- **FE.I18N3 M** Use locale-aware formatting/parsing for dates, times, numbers, currencies and pluralization; retain canonical data representations across boundaries.
- **FE.I18N4 M** Specify time-zone semantics for deadlines, appointments and logs. Distinguish absolute instants from wall-clock/local dates and avoid unintended client/server reinterpretation.
- **FE.I18N5 S** Prefer CSS logical properties and direction-aware UI elements; verify RTL/vertical or mixed-direction content when supported.
- **FE.I18N6 S** Design for text expansion, longer labels, non-Latin scripts, font coverage and varying word breaks; avoid fixed heights that cut off translated content.
- **FE.I18N7 M** Preserve legitimate Unicode, accents and punctuation; do not indiscriminately strip characters or normalize user identities/addresses using a universal rule.
- **FE.I18N8 M** Keep language selection, locale-aware URLs, document `lang`, SEO alternates and persisted preference coherent without using location or browser language as unquestionable authority.
- **FE.I18N9 S** Test representative translated copy/format edge cases rather than relying solely on pseudo-localization or English placeholders.
